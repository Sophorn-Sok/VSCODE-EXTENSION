## Findings

### 1. Generate Unit Tests / Generate Documentation time out — High

- **Symptom:** every run fails with *"Ollama did not finish within 300s… the model may still be loading."* Misleading — it wasn't loading, it was still generating.
- **Cause:** Ollama is called with `stream: false` ([`OllamaProvider.ts:47`](../src/core/OllamaProvider.ts#L47)), so nothing comes back until the full response is ready. Re-running the same request with the app's timeout raised to 900s still failed at 304.7s — with a *different* error this time — pointing to Node's built-in `fetch`, which has its own independent ~300s header timeout, unrelated to the app's own setting.
- **Why it's not a quick fix:** `timeoutMs` is hardcoded ([`OllamaProvider.ts:32`](../src/core/OllamaProvider.ts#L32)) and never exposed in Settings — but raising it wouldn't help, since Node's fetch layer would still cut the connection regardless. Needs a streaming request and/or a custom fetch dispatcher with a longer `headersTimeout`.

### 2. Stale reference docs in `sample-workspace/` — Medium

`API_Documentation.md` and `Architecture_Guide.md` both say their data is missing ("run Scan API Endpoints / Visualize Architecture first"), even though scanning the folder now finds 7 real endpoints and a real tree. They were generated once without those two prerequisite steps — a live example of Finding 1's neighbor bug: skipping a prerequisite fails silently into an incomplete doc. They're also now a misleading regression baseline for future diffs.

### 3. npm-failure pattern doesn't match current npm — Low

The `npm-error` signature matches `npm ERR!` ([`errorPatterns.ts:13`](../src/features/terminalErrorExplainer/errorPatterns.ts#L13)), but npm 9+ prints `npm error` instead (this env: npm 11.9.0). Detection still worked in testing, purely via a generic non-zero-exit fallback — not the npm-specific pattern itself. If shell integration ever fails to report the exit code, npm errors would go unexplained entirely.

### 4. Context-menu entry missed the first right-click — Low, unconfirmed

"Generate Unit Tests" was missing from the editor's right-click menu on the first try, present on every retry after. Explorer sidebar's menu had it both times. Possibly a Cursor-specific timing quirk rather than an extension bug — but a user hitting this once, with no reason to retry, would assume the feature doesn't exist.

## Recommendations, in priority order

1. **Fix the timeout (Finding 1)** — blocking; two of six features are unusable as shipped.
2. **Regenerate or remove the stale sample docs (Finding 2)**; consider a warning dialog for the missing-prerequisite case instead of buried markdown text.
3. **Extend the npm-error pattern (Finding 3)** to match `npm error`, not just `npm ERR!`.
4. **Watch for recurrence of the context-menu issue (Finding 4)** — no action needed unless it comes up again.
